# Threat model: SFTP sidebar

## 1. Component overview

How spec 0008 browses, edits, downloads and uploads files on an SSH pane's
host. Each SSH pane that the sidebar has shown gets an SFTP session: a
thread running `ssh … -s <host> sftp` with the `russh-sftp` client on its
stdio. The sidebar draws the session of the active pane. Edit copies live
under `<data_local_dir>/tern/edit/` and open in the OS's default app;
downloads go where the user picks; uploads come from files the user picks
or drops.

```
                TB1: network          TB2: ssh stdio / stderr        TB4: OS default app
remote host ──SFTP replies: names, ──► ssh ──► session thread ──► edit copy ──open──► editor, viewer
(sftpd)        sizes, contents, links  (OpenSSH)  (russh-sftp,       ▲  │ poll       │ saves
           ◄──requests, uploads─────── ◄──────── tokio)              │  └────────────┘
                                        ▲             │ channel      │ TB3: local filesystem
                    askpass, token:     │             ▼              │ (edit dir, Downloads,
                    threat model 0001   │       UI thread: sidebar ──┤  picked folders)
                                        │       (names, prompts,     │
                                        │        confirmations)      │
                                        │             ▲              │
                                        │       TB5: user ◄──────────┘
                                        │       file manager drops (TB6), file dialogs
```

Trust boundaries:

- **TB1** remote host ↔ local ssh: the server chooses every name, size,
  date, link target, file content and reply timing. A compromised or
  hostile server is in scope.
- **TB2** ssh ↔ session thread: SFTP packets on stdout, ssh's messages
  (and a server's pre-auth banner) on stderr.
- **TB3** session ↔ local filesystem: where remote-named files are
  written, and which local paths are read for uploads.
- **TB4** Tern → OS default app: `xdg-open` / `ShellExecute` on an edit
  copy, a file whose name and content the server chose.
- **TB5** sidebar ↔ user: which host a listing belongs to, confirmations
  for overwrites and deletes.
- **TB6** file manager → sidebar: dropped paths.

Out of scope: the SSH protocol, host keys and credentials (OpenSSH's, and
threat model 0001 for askpass), the user's own `~/.ssh/config`, bugs in
the user's default apps beyond how Tern reaches them, and an attacker
with root or running as the user.

## 2. Data classification

| Data | Category (GDPR) | Special constraints | Storage | Retention |
|---|---|---|---|---|
| Remote file contents | Can be anything: Art. 4(1) personal data, Art. 9 special categories, secrets (`.env`, keys) | Private user content: never logged, never cached beyond edit copies | Edit copies; where the user downloads | Edit copies until the session ends; downloads are the user's |
| Remote names, paths, sizes, dates | Art. 4(1) where they name people (home folders, documents) | Untrusted text (architecture §Security 1); never logged | Memory | Until the session ends |
| Host and user of a session | Art. 4(1): the user's accounts | Never logged | Memory, from the profile | Until the session ends |
| Askpass token of a session | Not personal data | Threat model 0001 | Memory, ssh's environment | ssh process lifetime |

No sector law applies: architecture §Ground rules names none, and the
data never leaves the user's device except to the host the user connects
to (the household case: no controller other than the user processes it).

## 3. STRIDE walkthrough

Impact and likelihood are H/M/L, judged with the spec 0008 design in
place; the status names the task that builds each mitigation.

| ID | STRIDE | Threat | Affected element | Impact | Likelihood | Mitigation | Status |
|---|---|---|---|---|---|---|---|
| TM-sftp-01 | Spoofing | With several SSH panes open, the user believes the sidebar shows host A while it shows host B, and uploads, overwrites or deletes on the wrong server. | TB5 | H | L | Each sidebar belongs to the SSH pane it was opened on and hides when another pane is focused, so it never shows one host beside another's terminal; the header always shows `user@host` from the pane's profile; every overwrite and delete confirmation names the host; a dialog belongs to its session and stays with it when focus moves. In `src/sftp/`. | mitigated (T-023) |
| TM-sftp-02 | Spoofing | A man in the middle poses as the host. | TB1 | H | L | ssh checks `known_hosts` as for the pane; a host-key question is an askpass dialog that never auto-answers (TM-askpass-07). | mitigated by design (spec 0006) |
| TM-sftp-03 | Tampering | A server-chosen name like `../../.bashrc`, `/etc/x`, `C:\x` or `a\b` writes a download or edit copy outside its folder. | TB1 → TB3 | H | M | One function in `src/sftp/` turns a remote name into a local file name by escaping as `%XX` every `/`, `\`, control character and Unicode `Cf` character, and the dots of a name that is `.` or `..`, so no name is a path; the result is joined to the target folder and refused, as a backstop, unless it is a direct child of it. Unit-tested with the hostile names of AC5. | mitigated (T-035) |
| TM-sftp-04 | Tampering | On Windows, a name like `x.txt:evil` writes an alternate data stream, `CON` or `aux.txt` hits a device, and a trailing dot or space makes the file name differ from what the check saw. | TB1 → TB3 | M | M | The same function on Windows also escapes `< > : " \| ? *`, the first character of a reserved device name (`CON`, `PRN`, `AUX`, `NUL`, `COM0-9`, `LPT0-9`, with any extension) and a trailing dot or space, so the name on disk is exactly the one checked. | mitigated (T-035), checked on Windows in T-011 |
| TM-sftp-05 | Tampering | A server names an executable so the OS runs it when the edit copy opens: `.exe`, `.lnk`, `.url`, `.hta`, `.js`, `.desktop`, … | TB4 | H | M | Only a copy the user clicked opens, through `open_with_system` only. Before opening, the name as written to disk is checked case-insensitively against Windows' `PATHEXT` plus the fixed lists of spec 0008 §Security; a hit is downloaded, not opened, and the sidebar says so. Copies never get an execute bit. In `src/sftp/`. | open → T-036 |
| TM-sftp-06 | Tampering | A name hides its real type: a right-to-left override shows `exe.txt` for `txt.exe`, or zero-width characters make two names look alike. | TB1 → TB5 | M | M | Names render by the title rules of spec 0003 (control, direction and invisible characters stripped); on disk those characters are escaped (TM-sftp-03), so the file manager shows `photo%E2%80%AEgpj.exe`, not the disguise; the open check (TM-sftp-05) uses the name on disk, so a hidden `.exe` is still never opened. | mitigated (T-023) |
| TM-sftp-07 | Tampering | A file opened as a document carries an exploit for the default app (PDF reader, Office macros). | TB4 | M | L | Windows: edit copies and downloads get `Zone.Identifier` with `ZoneId=3`, so Office's Protected View and SmartScreen apply as to any download. Linux has no equivalent; opening a document the user clicked is the same risk as any browser download. | Windows: mitigated for downloads (T-035), open → T-036 (edit copies); Linux: accepted (OQ-023) |
| TM-sftp-08 | Tampering | A download or edit replaces a local file the user didn't mean to lose. | TB3 | M | M | No download replaces an existing file without a confirmation; edit copies live in a fresh `<session>/<n>/` folder each, so they never collide. | mitigated for downloads (T-035), open → T-036 |
| TM-sftp-09 | Tampering | An upload clobbers a remote file someone changed since it was fetched, or an automatic upload (`save`, `focus`) writes a half-saved copy. | TB1 | M | M | Before each edit upload, the remote size and mtime are compared with the fetched ones, and a difference asks first; the poll marks a copy changed only when its size and mtime have held for one poll interval. A change between that stat and the write is a race we accept: SFTP has no compare-and-swap. | open → T-036; race accepted (OQ-023) |
| TM-sftp-10 | Tampering | Remote symlinks: a delete follows a link and removes its target, or a link to `/dev/zero` or a FIFO downloads forever. | TB1 | M | L | Delete uses SFTP `remove`/`rmdir`, which act on the link itself, never on a resolved path; a download whose size is unknown or growing shows bytes only and can be cancelled (flow 4); entering a link to a folder is a normal `stat` and `opendir`, and a loop is just a deep path. | mitigated (T-035) |
| TM-sftp-11 | Tampering | A dropped item is a symlink or a folder, so the upload sends something other than what the user saw. | TB6 | L | L | Folders are refused with a notice; a symlink to a file uploads its target's contents, as `scp` does, which is what the user dropped. | mitigated by design |
| TM-sftp-12 | Repudiation | An automatic upload (`save`, `focus`) changes a server file with no visible trace, and the user can't tell what went up when. | TB1, TB5 | L | M | Each edit row shows its state and the time of its last upload; there is no log file by design (no names or contents are ever logged). The server's own logs are the record. | open → T-036 |
| TM-sftp-13 | Information disclosure | Edit copies, which can hold secrets like `.env` files, are readable by other local users or outlive their session. | TB3 | H | L | Folders `0700`, files `0600` on Unix; on Windows `%LOCALAPPDATA%` is the user's by ACL. Copies are deleted when their session ends; after a crash, swept after the next launch's first frame. A copy the editor keeps (swap, backup, recent files) is outside Tern's reach. | open → T-036; editor leftovers accepted (OQ-023) |
| TM-sftp-14 | Information disclosure | Names, paths, contents or errors that quote them end up in a log or a crash report. | All | M | L | The sftp module logs nothing about sessions; errors shown in the sidebar are never written anywhere; Tern has no crash reporter. | mitigated (T-023) |
| TM-sftp-15 | Information disclosure | Hidden at the wrong time, a sidebar shows host A's listing over a pane of host B, for example in a screen share. | TB5 | L | L | The window draws a sidebar only for the active pane's own open session, never a stale one, and the header names the host (TM-sftp-01). | mitigated (T-023) |
| TM-sftp-16 | Spoofing | A server banner or crafted stderr text, shown as the failure reason, imitates a Tern prompt or a fake instruction ("run this to fix"). | TB2 → TB5 | M | L | ssh's stderr is shown as plain text, control characters stripped, capped at 1 KiB, under the label "ssh said:". Nothing in it is clickable or run. | mitigated (T-023) |
| TM-sftp-17 | Denial of service | A hostile server sends a huge listing, oversized packets, an endless stream, or stops answering, to exhaust memory or hang the sidebar. | TB1, TB2 | M | M | All SFTP work runs on the session's thread; the UI only draws what the channel delivers. A listing stops at 50,000 entries with a notice; packets over `russh-sftp`'s length cap end the connection; a request without a reply in 30 s ends it as dropped (flow 7). Transfers stream in 64 KiB requests, 16 in flight, so at most 1 MiB of a file is held. | mitigated (T-023, T-035) |
| TM-sftp-18 | Denial of service | A download fills the local disk. | TB3 | L | L | A failed write stops the download, deletes the partial file and says why. The user picked what to download. | mitigated (T-035) |
| TM-sftp-19 | Elevation of privilege | A host string from an imported or hand-edited profile starts with `-` and injects ssh options such as `-oProxyCommand=…` into the sftp command. | TB2 | H | L | The session builds its command with `ssh::command`, the same as the pane, and config parsing and import already drop hosts starting with `-` (`config.rs`, `import/mod.rs`); `-s` and `sftp` are added around the host by the session, never from config. | mitigated (existing guard; tested in T-023) |
| TM-sftp-20 | Elevation of privilege | A session's ssh or its `ProxyCommand` uses the askpass token to have the app fill in another target's password. | Askpass | H | L | Each session gets its own token; auto-fill matches only the connection's own prompts (TM-askpass-04, -19). | mitigated by design (threat model 0001) |

Every boundary of the sketch appears: TB1 in -02, -03, -04, -06, -09,
-10, -12, -17; TB2 in -16, -17, -19; TB3 in -03, -04, -08, -13, -18; TB4
in -05, -07; TB5 in -01, -06, -12, -15, -16; TB6 in -11.

## 5. Accepted risks

Signed off by the owner on 2026-11-06 ([OQ-023](../open-questions.md)):

- TM-sftp-07 (Linux): a document the user opens may exploit their default
  app; there is no mark-of-the-web on Linux.
- TM-sftp-09: a remote change between the pre-upload check and the write
  is overwritten; SFTP offers no atomic compare.
- TM-sftp-13: the user's editor may keep its own copies (swap files,
  backups, recent-file lists) of an edit copy after Tern deletes it.
